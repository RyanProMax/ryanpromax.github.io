## 1. 图形 API

Windows 系统的图形 API（Graphics Application Programming Interface）是软件接口，用于开发者创建和管理图形内容。相当于桥接层，在应用程序与底层硬件之间提供了一层抽象，开发者无需操作硬件接口即可进行图形绘制。

1. [GDI (Graphics Device Interface)](https://learn.microsoft.com/en-us/windows/win32/gdi/windows-gdi)：Windows 最基础的 2D 绘图接口，依赖`CPU`渲染，性能有限，主要供传统桌面应用使用。

2. [GDI+](https://learn.microsoft.com/en-us/windows/win32/gdiplus/-gdiplus-gdi-start)：GDI 的增强版，支持抗锯齿、透明度、复杂几何与高级文本渲染，仍以软件为主。

3. [Direct2D](https://learn.microsoft.com/en-us/windows/win32/direct2d/direct2d-portal)：面向 2D 的硬件加速 API，性能优于 GDI/GDI+，适合高性能绘图场景。

4. [Direct3D](https://learn.microsoft.com/en-us/windows/win32/direct3d12/direct3d-12-graphics)：DirectX 3D 渲染接口，广泛应用于游戏与高性能多媒体。

5. [OpenGL](https://www.opengl.org/Documentation/Specs.html)：跨平台的 2D/3D API，在 Windows 上通过驱动支持，多用于专业图形与部分游戏。

6. [WPF (Windows Presentation Foundation)](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/?view=netdesktop-6.0)：.NET 框架基于矢量的 UI 子系统，内置动画、样式与硬件加速，适合快速构建现代桌面应用。

7. [Vulkan](https://docs.vulkan.org/spec/latest/index.html)：Khronos Group 提供的低开销、跨平台图形/计算 API，面向极致性能和细粒度控制。

## 2. 游戏进程采集

- **原理**：把 DLL 注入目标进程，在它提交画面时把后台缓冲拷出来。拦截点按 API 分开：D3D9 没有 DXGI 交换链，钩的是 `IDirect3DDevice9::Present`；D3D10/11/12 钩 `IDXGISwapChain::Present`；OpenGL 钩 `wglSwapBuffers`；Vulkan 钩 `vkQueuePresentKHR`。拷贝走共享 GPU 纹理，采集进程打开这张纹理取帧。

- **优点**：

  - 能采集独占全屏。这种画面绕过 DWM，WGC 和 BitBlt 都读不到；注入发生在进程内部的 Present 上，所以读得到。
  - 帧率跟着游戏自己的 Present，不跟显示器刷新率。60Hz 显示器上以 144fps Present 的游戏，采集仍按游戏的提交节奏出帧。
  - 窗口被挡住也不影响，读的是后台缓冲，不是桌面上已经合成好的像素。
  - 拷贝留在 GPU 上，不必先读回 CPU。

- **缺点**：

  - 只对通过 D3D、OpenGL、Vulkan 提交画面的程序有效。纯 GDI 窗口没有这些调用，无钩可挂。
  - 多进程沙箱（例如 Electron / Chromium 的 GPU 进程）很难注入。
  - 杀毒软件和反作弊会拦截 DLL 注入；钩子如果和已经释放的交换链发生冲突，会直接把游戏打崩。
  - 每套 API 的提交函数和交换链生命周期都不同，要分别适配。
  - 游戏以管理员身份运行时，采集进程也必须以管理员身份运行，否则系统会拒绝注入。

## 3. 窗口采集

DWM 开启后，每个顶层窗口先画到自己的屏外重定向表面，再由 DWM 合成进桌面。下面几种方式的差别，就是读合成前的窗口内容，还是读合成后的桌面。

### [Windows.Graphics.Capture（WGC）](https://learn.microsoft.com/zh-cn/windows/apps/develop/media-authoring-processing/screen-capture)

- **原理**：`Windows.Graphics.Capture` 向 DWM 要一个窗口在桌面合成之前的完整内容，包括 DWM 拿去合成的 GPU 纹理，以 D3D11 纹理交回调用方。遮挡是合成时才叠上去的，所以窗口被别的窗口挡住不影响。GDI 窗口和 GPU 窗口都能采到，因为读的是这份窗口内容，不是 GDI 重定向位图，也不是合成完的整张桌面。最小化后窗口通常停止绘制，没有新的表面可读。独占全屏绕过 DWM，这套 API 看不到那一帧。

  按窗口采集时，尺寸跟着窗口走（`GraphicsCaptureItem.Size`）。帧率跟着 DWM 的合成，上限是这块显示器的刷新率。同一台 60Hz 显示器上，窗口化或无边框、仍由 DWM 合成的 144fps 游戏，WGC 不会按 144fps 出帧。

  这套 API 在 Win10 1803 就有，但当时只能弹出系统选择器 `GraphicsCapturePicker`。按句柄指定窗口或显示器，要走 [`IGraphicsCaptureItemInterop`](https://learn.microsoft.com/zh-cn/windows/win32/api/windows.graphics.capture.interop/nn-windows-graphics-capture-interop-igraphicscaptureiteminterop) 的 `CreateForWindow` / `CreateForMonitor`，最低版本是 Win10 1903。1803 和 1809 都没有这两个方法。1803 之前的 Windows 10，以及 Win7，没有这套 API。DXGI Desktop Duplication 是另一套接口，按显示器复制已经合成好的桌面，见下一节。

- **优点**：

  - GDI 和 GPU 绘制的窗口都能采，窗口被挡住也不影响。
  - 帧是调用方 D3D11 设备上的纹理，不必读回 CPU，也不注入目标进程。
  - 没有 Desktop Duplication「设备必须创建在输出所在适配器上」的限制，采集端和目标窗口可以不在同一块显卡。

- **缺点**：

  - 按句柄采集需要 Win10 1903+。1803 和 1809 只有系统选择器。
  - 采不到独占全屏。最小化的窗口通常是黑的，或不再更新。
  - Win10 上，被采集的窗口或显示器边缘有一圈黄色边框。Win11 起可以设 [`IsBorderRequired`](https://learn.microsoft.com/zh-cn/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired) 为 false。文档要求先用 `GraphicsCaptureAccess.RequestAccessAsync` 取得 `GraphicsCaptureAccessKind.Borderless` 同意，打包应用还要声明 `graphicsCaptureWithoutBorder`；别的程序如果仍要求边框，边框会留下。
  - 双显卡笔记本上，游戏在独显、采集纹理在核显时，跨适配器拷贝仍可能黑屏或异常。

### [DXGI Desktop Duplication](https://learn.microsoft.com/zh-cn/windows/win32/direct3ddxgi/desktop-dup-api)

- **原理**：Win8 起的 [`IDXGIOutput1::DuplicateOutput`](https://learn.microsoft.com/zh-cn/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutput1-duplicateoutput)。按显示器输出拿到桌面图像，是一块 GPU 上的 DXGI 纹理，再按窗口矩形自己裁剪。读的是 DWM 合成之后的桌面。D3D 设备必须创建在连接这块输出的适配器上。Win7 即使装了 Platform Update，这个接口也返回 `E_NOTIMPL`。

- **优点**：

  - 画面以 DXGI 表面留在 GPU 上，还可以查询脏矩形，比 BitBlt 拷到 CPU 轻，适合整屏、整台显示器的采集。
  - Win8 到 Win10 1903 之前还不能按窗口句柄用 WGC，这段时间它是可用的 GPU 采集路径。

- **缺点**：

  - 只能按输出采集。裁到窗口矩形时，挡在上面的内容也在画面里。
  - 真正独占输出、把 DWM 挤掉的全屏游戏，不在这张桌面图像里。接口文档写明它支持 DWM 桌面，以及非 8bpp 的 DirectX / OpenGL 全屏模式。
  - 同一输出上，一个进程同时只能有一份复制；一个会话里同时复制的进程默认最多四个，超限返回 `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`。

### [GDI BitBlt](https://learn.microsoft.com/zh-cn/windows/win32/api/wingdi/nf-wingdi-bitblt)

- **原理**：DC（Device Context，设备上下文）是 GDI 里指向一块绘图表面的句柄。`BitBlt` 把像素从一个 DC 拷到另一个 DC。采到什么，取决于源 DC 指向哪块表面。

  DWM 下，窗口的 GDI 绘制进自己的屏外重定向位图，再参与桌面合成。

  - 窗口 DC（`GetDC(hwnd)` / `GetWindowDC`）读的就是这块位图。普通 GDI 窗口即使被挡住，位图里仍有内容。
  - D3D 的 flip-model 交换链，以及 Chrome / Electron 使用的 DirectComposition，画在另外的 GPU 纹理里。DWM 合成时直接采样这些纹理，不写进 GDI 位图。Chrome / Electron 还会加上 `WS_EX_NOREDIRECTIONBITMAP`，直接不创建这张位图。对它们做窗口 DC 的 BitBlt，结果是黑的。更早的 blit 模型如果画进了重定向位图，窗口 DC 仍可能采到。
  - 屏幕 DC（`GetDC(NULL)`）再按窗口矩形裁剪，读的是合成之后的桌面。GPU 窗口能采到，挡在上面的窗口也会被采进去。
  - [`PrintWindow`](https://learn.microsoft.com/zh-cn/windows/win32/api/winuser/nf-winuser-printwindow) 默认让目标窗口处理 `WM_PRINT`，GPU 窗口经常仍是黑的。加上 `PW_RENDERFULLCONTENT`（Windows 8.1+，定义在 `winuser.h`）后，DWM 会把整个窗口画进目标 DC，包括 DirectComposition / GPU 层。Chrome、Electron 这类窗口很多可以这样采到，被挡住时也能用。调用是同步的。独占全屏，以及设置了显示亲和性的内容，仍然不行。

- **优点**：

  - 所有带 GDI 的 Windows 版本都能用，是通用退路，不只给老系统。
  - 不需要额外权限，也不需要系统选择器。纯 GDI 窗口用窗口 DC 即可，被遮挡也不影响。

- **缺点**：

  - 窗口 DC 拿不到 flip-model 和 DirectComposition 的 GPU 画面。
  - 屏幕 DC 能看到已经合成进桌面的 GPU 窗口，但遮挡会进画面，独占全屏仍然采不到。
  - 像素拷到 CPU，分辨率高时开销大。

### [Magnification API](https://learn.microsoft.com/zh-cn/windows/win32/winauto/magapi/magapi-intro)

- **原理**：放大镜控件把屏幕上的一块源矩形拷进离屏位图（`MagSetWindowSource`）。读的是 DWM 合成之后的桌面，和屏幕 DC 的 BitBlt 同一层，但路径不同：不经过 WGC，也不经过 DXGI Desktop Duplication。[`MagSetWindowFilterList`](https://learn.microsoft.com/zh-cn/windows/win32/api/magnification/nf-magnification-magsetwindowfilterlist) 用 `MW_FILTERMODE_EXCLUDE` 可以排除指定窗口，例如采集端自己的预览和浮层；放大镜窗口自己会被自动排除。最小化的窗口已经不在合成结果里，排除别的窗口也把它变不出来。`MW_FILTERMODE_INCLUDE` 从 Windows 7 起不支持。全屏放大镜不支持过滤列表。WebRTC 的屏幕采集里有一套这个 API 的实现。

- **优点**：

  - 放在降级链最后一档时，前面都失败了它还有机会出帧。老系统没有 WGC；Win7 上 `DuplicateOutput` 返回 `E_NOTIMPL`。一部分驱动、双显卡和远程会话环境里，桌面复制也会失败。放大镜不走那条接口，这些环境里有时仍能拿到合成后的桌面。
  - 能排除采集程序自己的预览和浮层。同样是读合成桌面，画面比屏幕 DC 的 BitBlt 干净，屏幕 BitBlt 会把这些窗口一起裁进去。

- **缺点**：

  - 和屏幕合成是同一层。独占全屏、`SetWindowDisplayAffinity` 保护的窗口、最小化的窗口，它也采不到。它是让画面别空着的最后一档，不是万能解法。
  - 像素在 CPU 上，开销比前几档高。[`MagSetImageScalingCallback`](https://learn.microsoft.com/zh-cn/windows/win32/api/magnification/nf-magnification-magsetimagescalingcallback) 从 Windows 7 起弃用，只在 DWM 关闭时有效，没有替代回调。
  - 一个进程只能用一个放大镜实例。它面向整块桌面，不是按窗口句柄采集。32 位进程在 64 位 Windows 上不受支持（WOW64）。

## 4. 为什么仍然会采集失败

WGC 和 BitBlt 都接上之后，线上仍会黑屏或画面冻结。常见原因：

1. **画面没有进 DWM 正在读的那一层。** 独占全屏会绕过 DWM。无边框全屏可能走 independent flip（direct flip）：交换链直接交给显示器扫描。硬件 overlay（MPO，multiplane overlay）把视频或 HDR 放在单独的硬件平面上。这些像素可能不在 WGC 和 BitBlt 拿到的表面里，表现是黑屏，或停在旧帧上。

2. **窗口拒绝被采集。** 目标程序调用 [`SetWindowDisplayAffinity`](https://learn.microsoft.com/zh-cn/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)。`WDA_EXCLUDEFROMCAPTURE`（Win10 2004 起）让窗口在采集结果里不出现；`WDA_MONITOR` 让采集结果里这块区域没有内容。两者都只在 DWM 正在合成桌面时生效。

3. **窗口状态或句柄不对。** 最小化后程序通常停止绘制，WGC 没有新表面，按屏幕裁剪也截不到它。窗口在屏幕外时，屏幕 DC 和 DXGI 按桌面矩形裁，裁到的是别的内容或空白；WGC 有时仍能拿到窗口表面，但程序若因此停止绘制，一样是黑的或冻住。另一张虚拟桌面上的窗口可能被 cloak。句柄如果是子窗口或启动器窗口，采到的就不是正在绘制的那一层。

4. **显卡、格式和会话。** 混合显卡笔记本上，游戏在独显，采集用的纹理在核显。驱动对共享纹理或桌面复制支持不完整时，也会黑屏或冻帧。开了 Windows HD Color 时，内容像素格式不一定是官方示例里的 `DXGI_FORMAT_B8G8R8A8_UNORM`，直接当 8-bit 用会发灰（文档称为 pixel overclipping），HDR 需要改用 `DXGI_FORMAT_R16G16B16A16_FLOAT` 这一类格式。远程桌面里经常拿不到同一块桌面表面；会话断开时 Desktop Duplication 返回 `DXGI_ERROR_SESSION_DISCONNECTED`。

5. **权限和安全桌面。** 注入要求调用方的完整性级别足以打开目标进程。UAC 同意界面和锁屏在安全桌面上，普通用户进程进不去。Desktop Duplication 对安全桌面返回 `E_ACCESSDENIED`，文档写明只有 `LOCAL_SYSTEM` 能访问。

## 5. 使用建议

1. 游戏优先用进程注入。这条路径能采到独占全屏，帧率也跟着游戏的 Present。
2. 注入不可用，且系统是 Win10 1903 及以上时，用 WGC 按窗口采集。
3. 再往下用 DXGI Desktop Duplication，或屏幕 DC 的 BitBlt，按窗口矩形裁剪。
4. 上面仍然没有可用画面时，用 Magnification 做最后一档。它用另一条路径读合成后的桌面，并能排除采集端自己的窗口，用来把画面留住。
5. 确认目标是纯 GDI 窗口时，可以直接用窗口 DC 的 BitBlt，被遮挡也能采到。这是一条捷径，不插在上面的降级链里。
6. 用黑帧和冻帧检测沿这几档自动往下切换，并把失败原因打进遥测。
